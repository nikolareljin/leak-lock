Your secret isn't in your repo.It's in your refs.

Leak Lock scans a repository's full git history for credentials, then removes them from every branch and tag — including the ones that exist only on the remote, which is where most cleanups quietly leave the key behind.

    Credentials in your files

    Credentials in your history

    how it removes · v0.6.0

    Nine steps, in this order

    The order is the point. Every rewrite — BFG, filter-branch, or filter-repo — runs this sequence, whether you press the button in the panel or copy the generated script and run it yourself.

    git fetch --prune --tags

    Plan against current refs, not whatever your last fetch happened to leave behind.

    Check for unpushed commits

    Step 4 resets local branches to their remote counterparts. If a local branch is ahead, those commits would be discarded — so the rewrite stops and names the branches instead.

    Detach HEAD

    Git refuses to force-update the branch you're standing on. Without detaching, the loop below silently skips exactly that branch.

    Create a local branch for every remote branch

    This is the step that closes the leak. git push --force --all expands to refs/heads/* only, so a branch that exists solely as refs/remotes/origin/* gets rewritten locally and never pushed — and the old history returns on your next fetch.

    Rewrite across all refs

    BFG for speed, filter-branch for exact paths, or filter-repo for text replacement. All of them run over every ref.

    Drop backup refs, expire the reflog, repack

    refs/original/* and the reflog still point at the old objects. Until they're gone, so is the secret — locally, at least.

    git push --force --atomic

    Atomic matters: if one ref is rejected — a protected branch, say — the server rejects the whole push, instead of leaving you with some branches clean and others still leaking.

    Restore your branch

    You end up back on the branch you started from, not detached at some rewritten commit.

    Verify every ref on the server

    Re-fetch, then check each remote branch and tag. Anything still carrying the secret is reported by name. A cleanup you can't verify isn't finished.

    what to expect

    It rewrites history. Plan for that.

    Removing a secret from git means rewriting every commit that touched it. Here's what that costs, and what the extension does to keep it survivable.

    ! Every commit hash changes

    Everyone working on the repository re-clones or hard-resets after the rewrite. Agree on a time before you run it.

    ! Unpushed work blocks the rewrite

    If a local branch has commits the remote doesn't, the rewrite stops and lists them. Push them first — Leak Lock won't discard them for you.

    ! The credential is already compromised

    Anything that reached a remote should be treated as leaked. Rotate the credential first; cleaning history is the second step, not the first.

    ✓ Nothing runs without review

    Every cleanup is prepared first: a full script you can read, save, and run yourself, plus a plan naming each ref that will be force-updated.
